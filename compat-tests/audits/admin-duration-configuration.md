# Admin fractional durations and truthy defaults

Pinned Better Auth 1.7.6 `plugins/admin/routes.mjs` uses truthy fallback for ban
duration, ban reason and impersonation lifetime. Zero request durations select
the configured default; zero/NaN configuration values act as absent, while
negative and fractional values remain meaningful. Empty reasons select the
configured nonempty reason or 'No reason'. `utils/date.mjs` constructs a Date
from Date.now plus seconds times 1000, retaining fractional milliseconds until
the complete timestamp undergoes JavaScript TimeClip truncation.
Actual installed-runtime cases are retained in `/tmp/admin-duration-oracle.log`,
`/tmp/admin-duration-boundaries-oracle.log` and
`/tmp/admin-duration-config-dates-oracle.log`. Actual request-handler probes in
`/tmp/admin-duration-http-oracle.log` prove infinite/overflow configured dates
return empty HTTP 500 without user or session writes for an unbanned target.

The two public AdminConfig duration fields and HTTP ban request duration now use
f64. Local date construction checks nonfinite values and JavaScript Date bounds
before integer conversion, truncates the complete millisecond timestamp, and
checks native date representability. A private typed operation error marks date
construction failures; only that variant maps to empty 500 in the two HTTP
wrappers. Authorization, database and application hook AuthErrors pass through
unchanged. Request nonfinite numbers retain rejection at the body boundary.
No string matching, general error suppression, mutable clock, global base URL,
sleep, comparator exemption or new production test seam is introduced.

The separate 5089720 nullable-expiry prerequisite supplies outer-None omission
and inner-None clearing. Ban operations now explicitly assign Some(nullable
date), so re-banning without a truthy duration clears an earlier expiry in one
normal update. There is no temporary unban or extra write. The separate 9af0288
snapshot prerequisite retains original response users when an expired ban is
cleared during session creation; the stored unban and session binding remain
authoritative. Their local cherry-picks are 328f632 and d7208470 respectively;
this capability commit contains only its own duration/fixture/test/audit delta.

Five official-client scenarios are the primary owners. Immutable actual plugin
profiles cover zero, fractional, negative, NaN and infinite configuration, plus
real application database hooks. Actual SQLite state observations retain ban
fields, generated dates, credential ownership and complete session identifiers,
tokens, owners and dates. Positive/failure flows exercise target session
revocation, ban refusal, expired-ban sign-in, impersonation/current-session
binding and expiration, re-ban clearing, and unchanged acting/foreign owners.
Fractional durations are asserted against dates generated by the same server
operation, within 100ms; the original raw dates and all result/cookie/transport
fields remain compared. No local clock or delay generates expected state.
Genuine configured 403 and 500 hook API errors use the same 'Invalid Date' text
and must retain their distinct structured code/message, preventing a blanket
or message-based invalid-date mapper from passing.

Unchanged da0cada production fails the two initial SDK owners in
`/tmp/admin-duration-before.log`: empty reason is persisted and fractional
request duration is rejected as an integer. A distinct actual endpoint control
in `/tmp/admin-duration-reban-before.log` retains all repaired numeric behavior
but uses the mechanical prerequisite's omission assignment; it fails because
zero re-ban retains the actual earlier stored expiry. Reinstating the explicit
clear passes. Source-to-source controls pass five scenarios/364 assertions in
`/tmp/admin-duration-oracle-sdk-final.log`; the repaired whole admin family
passes 22 scenarios/928 assertions in `/tmp/admin-duration-sdk-final.log`.
The existing 12 native admin tests, strict API/SeaORM and fixture Clippy, actual
fixture build and TypeScript checks are recorded in
`/tmp/admin-duration-{native,clippy,fixture-clippy,build,typecheck}-final.log`.
Formatting and diff checks are complete. Inventories, locks, canonical gates
and publication remain coordinator-owned.

Boundaries: chrono represents a slightly narrower date range than JavaScript;
valid JavaScript dates outside that native range are not claimed supported.
Detailed Zod validation errors and null/type coercion branches remain separate.
Invalid-date repair/reordering by custom adapter or session hooks, arbitrary
slow callback timing and nonstandard stores are unproved. The preserved native
<= ban-expiry comparison versus source strict < is a separately tracked boundary.
Async banned-user-message callbacks and trusted public server API dispatch are
later capabilities. No schema, migration, lock, inventory or dependency edit
belongs to this duration commit.

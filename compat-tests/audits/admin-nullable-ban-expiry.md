# Nullable ban-expiry storage contract

Pinned Better Auth 1.7.6's admin ban operation passes an explicit `banExpires: null` when no duration is effective. Its adapter updates that field to SQL NULL; omitted fields are retained. Rust's previous `UpdateUser.ban_expires: Option<DateTime<Utc>>` could set a date or omit the column but could not clear an earlier date without also unbanning the user.

The public Rust patch now uses `Option<Option<DateTime<Utc>>>`: outer `None` omits the expiry, `Some(None)` clears it, and `Some(Some(date))` sets it. Serde preserves omitted versus explicit-null fields through a trusted patch roundtrip. Generated entities, the manual numeric-ID integration entity, and the in-memory test store assign the inner nullable value. Existing HTTP callers are adapted mechanically, preserving their current behavior; the separate duration slice will use the explicit clear for an indefinite replacement ban. User/model/wire expiry types and the already nullable physical column are unchanged. No migration or dependency changes are required.

One owner-boundary native test exercises real public `SeaOrmStore` updates against both generated string-ID and application-owned numeric-ID entities. Actual JSON patches set, omit, clear, reset and clear again. SQL readback proves physical NULL, while the user stays banned with its reason/name/email preserved. Complete foreign user and owner/foreign session snapshots remain unchanged. The two schemas exercise distinct generated/manual binding risks in one test owner. The existing expired-ban sign-in proof remains separate HTTP lifecycle coverage.

Before repair, the identical native owner failed because explicit JSON null retained `2030-01-02T03:04:05.125Z` rather than clearing it (`/tmp/nullable-ban-expiry-native-before.log`). Existing schema and admin stateful siblings pass after repair. Final focused checks and full integrated measurements are recorded when publication occurs. No new production route, test-only seam, update-user authorization claim, duration policy, or full parity claim is introduced.

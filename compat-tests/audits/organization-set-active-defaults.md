# Set-active organization defaults: Better Auth 1.7.6

This bounded follow-up ports actual failed default selector, rejection, and early-return branches. The prior raw-metadata projection remains intact; this does not claim cookie-cache configurations, hook/adapter customizations, or complete organization parity.

## Source contract and repair

The pinned `better-auth/dist/plugins/organization/routes/crud-org.mjs::setActiveOrganization` distinguishes an explicit null ID from missing/empty selectors. Null takes precedence over a supplied slug. It clears a selected current session and writes a cookie, but returns null without a session update/cookie when already unselected. Missing/empty ID and slug reuse a nonempty current selection, or return null without a cookie if no selection exists. A nonempty ID takes precedence over slug; an empty ID allows a nonempty slug to resolve. A failed slug lookup leaves the prior selection intact.

Membership is checked before organization lookup and selection assignment. A nonmember ID, including an unknown ID, clears only the authenticated current token and throws 403 `USER_IS_NOT_A_MEMBER_OF_THE_ORGANIZATION`; it does not change the user's other selected token or issue a cookie. A successful lookup writes the returned organization's ID and emits its stored metadata response through the previously repaired projection.

The Rust core now follows those truthy-string and query/write branches. The handler's cookie condition is derived from all successful source returns: a returned organization always follows a selection update; a null result follows a clear only when the original session had a nonempty selection; all other null results are the source early returns. The tests independently exercise explicit null on selected and unselected sessions, omitted selectors on an unselected session, blank selectors on selected/unselected sessions, and null taking precedence over a slug. The condition is not a general adapter write-detection contract, and concurrent session deletion/customized session write results remain separate.

`better-call/dist/utils.mjs`, `router.mjs`, and `context.mjs` establish media/decoding/ordered endpoint validation before session middleware. The private organization parser now ports the set-active nullable optional string ID and optional string slug, preserving declaration-order errors. Valid guests receive the source 401 `UNAUTHORIZED`; malformed guest fields receive 400 `VALIDATION_ERROR` before authentication, and unsupported media receives 415 before JSON parsing. No public DTO, store interface, shared selector helper, callback, or schema changes were needed.

## Meaningful default evidence

An independent unchanged pinned runtime probe confirmed every repaired discrepancy before implementation: blank ID/slug returned the selected organization upstream but 403 in Rust; wrong-owner selection cleared only the upstream current token; unselected null/omitted selectors emitted no upstream cookie while Rust emitted one; malformed guest fields reached upstream validation while Rust authenticated first; valid guest error codes differed. Missing slug already had the correct 400, and its selection-preservation control is retained.

Two official-client scenarios in `tests/organization-extensions/set-active-defaults.test.ts` own the lifecycle and transport boundaries. Real SQLite observations include organization/member identity and role, raw metadata text, logo, session tokens and their active IDs, and unowned rows. Two tokens for one owner begin on different owned organizations; a separate owner retains a third organization. The cases verify legitimate blank/slug/ID precedence, missing slug preservation, selected null clear, separate unselected null/omitted/blank no-cookie responses, and successful restoration. A wrong-owner mixed ID/owned-slug request rejects with only the current token cleared, while all memberships/metadata/other token/foreign rows remain unchanged. Ordered malformed and valid guests plus a malformed body with unsupported media cannot alter those records. An unknown explicit ID follows the same membership-denial branch after a successful retry.

Both scenarios fail against the frozen previous implementation (`113964f`) for the intended reasons: blank selectors receive 403 instead of a selected organization, and the denied request leaves the current SQL session selection unchanged. After repair, both pass with 152 assertions. Their raw traces still compare complete response shapes, cookies, and wire statuses; no fixture success, comparator exemption, or inventory relaxation was introduced. Existing creation/input/patch/raw-metadata/core organization proofs run unchanged as siblings. Final focused validation passed 44 SDK scenarios / 2568 assertions, 32 organization API tests, strict API library Clippy, client TypeScript, workspace Rust formatting, and diff validation.

Configured cookie caches/lifetimes, session database hooks, custom adapters/fields, concurrent lookup/write failures, nullable metadata storage/migration, and uncommon composite media/empty-stream behavior remain separate boundaries. No new native duplicate of the HTTP lifecycle tests was added.

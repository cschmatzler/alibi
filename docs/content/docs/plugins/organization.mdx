The `OrganizationPlugin` provides multi-tenancy support with organizations, membership management, invitation workflows, and role-based access control (RBAC).

## Setup

These examples assume you've already defined `AppAuthSchema`. If you want a complete setup from entity definitions through Axum mounting, start with the [Axum integration guide](/docs/integrations/axum).

```rust
use better_auth::plugins::OrganizationPlugin;

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .plugin(OrganizationPlugin::new())
    .build()
    .await?;
```

### Configuration

```rust
use better_auth::plugins::organization::OrganizationConfig;

let auth = BetterAuth::<AppAuthSchema>::new(config)
    .store(store)
    .plugin(
        OrganizationPlugin::new()
            .allow_user_to_create_organization(true)
            .organization_limit(5)
            .membership_limit(50)
            .creator_role("owner")
            .invitation_expires_in(172800) // 48 hours
            .invitation_limit(100)
    )
    .build()
    .await?;
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `allow_user_to_create_organization` | `bool` | `true` | Allow users to create organizations |
| `organization_limit` | `Option<usize>` | `None` | Max organizations per user |
| `membership_limit` | `Option<usize>` | `Some(100)` | Max members per organization |
| `creator_role` | `String` | `"owner"` | Role assigned to organization creator |
| `invitation_expires_in` | `u64` | `172800` (48h) | Invitation expiration in seconds |
| `invitation_limit` | `Option<usize>` | `Some(100)` | Max pending invitations per org |
| `disable_organization_deletion` | `bool` | `false` | Prevent organization deletion |
| `roles` | `Option<HashMap<String, RolePermissions>>` | `None` | Replace the default roles when a map is supplied |
| `teams` | `TeamsConfig` | Disabled | Enable teams, default-team creation, limits, and callbacks |
| `require_email_verification_on_invitation` | `Option<bool>` | `None` | Require a verified recipient; defaults to true with numeric database IDs |

### Teams

```rust
use better_auth::plugins::organization::{OrganizationConfig, TeamsConfig};

let organization = OrganizationPlugin::with_config(OrganizationConfig {
    teams: TeamsConfig {
        enabled: true,
        maximum_teams: Some(10),
        maximum_members_per_team: Some(25),
        ..Default::default()
    },
    ..Default::default()
});
```

Enabling teams creates a default team and creator membership when an organization
is created. Set `create_default_team: false` to start with no teams, or
`allow_removing_all_teams: true` to permit removing the final team. A custom
`DefaultTeamFactory` can persist and return a different default team. Its context
contains the actual request, authenticated user and session, and auth configuration.

`OrganizationLimitResolver` supports asynchronous limits. Its maximum-teams
callback receives the current request and principal, while its member-limit callback
receives the team and principal. `OrganizationTeamHooks` can mutate or veto team and
membership changes before they are written, and observe successful writes afterward.

Invitations accept one team ID or a list of team IDs. Acceptance writes the
organization and team memberships together, with recipient, session, tenant, and
capacity checks. A single-team invitation selects that team; a multi-team invitation
preserves the current selection. Creating an organization with
`keepCurrentActiveOrganization: true` preserves both active organization and team.

The Rust `OrganizationPlugin::create_team` and `remove_team` methods are server-only
interfaces that take an explicit organization scope and auth context. HTTP team
operations require an authenticated user and the relevant organization permission.

## RBAC (Role-Based Access Control)

### Default Roles

| Role | Organization | Member | Invitation | Team | API key |
|------|-------------|--------|------------|------|---------|
| **owner** | update, delete | create, update, delete | create, cancel | create, update, delete | — |
| **admin** | update | create, update, delete | create, cancel | create, update, delete | — |
| **member** | — | — | — | — | — |

The `apikey` resource governs organization-owned keys from the [API Key plugin](/docs/plugins/api-key#named-configurations-and-organization-owned-keys). Matching upstream, no default role is granted any action on it; the creator role (`creator_role`, `"owner"` by default) is allowed everything implicitly, and other roles need an explicit grant through a custom role.

### Custom Roles

`roles: None` uses the default roles. `Some(map)` replaces them, and
`Some(HashMap::new())` supplies an explicitly empty role policy. A permission request
must be satisfied by one of a member's assigned roles; separate roles do not combine
their grants to satisfy the same request.

```rust
use better_auth::plugins::organization::{OrganizationConfig, RolePermissions};
use std::collections::HashMap;

let mut roles = HashMap::new();
roles.insert("editor".to_string(), RolePermissions {
    organization: vec!["update".to_string()],
    member: vec!["update".to_string()],
    invitation: vec![],
    api_key: vec!["read".to_string(), "create".to_string()],
    team: vec!["update".to_string()],
    ..Default::default()
});

let config = OrganizationConfig {
    roles: Some(roles),
    ..Default::default()
};

let auth = BetterAuth::<AppAuthSchema>::new(auth_config)
    .store(store)
    .plugin(OrganizationPlugin::with_config(config))
    .build()
    .await?;
```

### Resources and Actions

**Resources**: `organization`, `member`, `invitation`, `team`, `apikey`

**Actions**: `create`, `read`, `update`, `delete`, `cancel`

## API Endpoints

The Organization plugin exposes 21 organization endpoints and nine additional team
endpoints when teams are enabled. For request/response details, see the
[OpenAPI Reference](/docs/reference/openapi/organization).

### Organization CRUD

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/organization/create` | POST | Create a new organization |
| `/organization/update` | POST | Update organization details |
| `/organization/delete` | POST | Delete an organization |
| `/organization/list` | GET | List user's organizations |
| `/organization/get-full-organization` | GET | Get organization with members and invitations |
| `/organization/check-slug` | POST | Check slug availability |
| `/organization/set-active` | POST | Set active organization on session |
| `/organization/leave` | POST | Leave an organization |

### Member Management

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/organization/get-active-member` | GET | Get current member record |
| `/organization/get-active-member-role` | GET | Get the current member role |
| `/organization/list-members` | GET | List organization members (with pagination) |
| `/organization/remove-member` | POST | Remove a member (requires `member:delete`) |
| `/organization/update-member-role` | POST | Update member role (requires `member:update`) |

### Invitations

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/organization/invite-member` | POST | Invite a user by email |
| `/organization/get-invitation` | GET | Get invitation details |
| `/organization/list-invitations` | GET | List organization invitations |
| `/organization/list-user-invitations` | GET | List invitations for current user (requires a verified email) |
| `/organization/accept-invitation` | POST | Accept an invitation |
| `/organization/reject-invitation` | POST | Reject an invitation |
| `/organization/cancel-invitation` | POST | Cancel an invitation (requires `invitation:cancel`) |

### Permission Check

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/organization/has-permission` | POST | Check if user has specific permissions |

### Team Management

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/organization/create-team` | POST | Create a team |
| `/organization/update-team` | POST | Update a team |
| `/organization/remove-team` | POST | Remove a team |
| `/organization/list-teams` | GET | List organization teams |
| `/organization/list-user-teams` | GET | List the current user's teams |
| `/organization/list-team-members` | GET | List team members |
| `/organization/set-active-team` | POST | Select a team or clear the selection |
| `/organization/add-team-member` | POST | Add an organization member to a team |
| `/organization/remove-team-member` | POST | Remove a team member |

## Errors

| Status | Condition |
|--------|-----------|
| 400 | Invalid slug format or missing required fields |
| 403 | Insufficient permissions for the operation, or `EMAIL_VERIFICATION_REQUIRED_FOR_INVITATION` when listing invitations with an unverified email |
| 404 | Organization, member, or invitation not found |
| 409 | Slug already taken or user already a member |

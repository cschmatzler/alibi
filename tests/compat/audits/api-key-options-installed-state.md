The primary proof will extend the real official-client boundary with configured

The authoring gate is satisfied by distinct uncovered risks: integer-only
configuration cannot express the Source options; lossy substring conversion
loses persisted lone-surrogate bytes; typed permission revalidation changes
installed access-control behavior; and private verifier response wrapping loses
its actual response content type. Credible before failures are recorded before
the corresponding repairs are considered proved. Production types preserve real
configuration/code-unit inputs used by generators and stores, with no test-only
flag, callback receipt, fake key or permission result.

Read-only pinned Source evidence is `/tmp/issue204-source-owners.log`:
fractional built-in lengths .5/1.5/2.25 terminate with 1/2/3 characters; zero and
NaN normalize to 64; negative lengths throw before insertion. A real custom
generator observes nonfinite and sub-.5 lengths. The built-in positive infinity
and positive lengths below .5 are never invoked because they cannot provide a
bounded terminating probe. Numeric comparisons and substring coercion preserve
raw options instead of silently rounding configuration.

A one-code-unit cut through the actual generated `😀` prefix persists SQLite
TEXT bytes `EDA0BD`, which Bun reads as three replacement characters. Proof
must retain both `hex(CAST(start AS BLOB))` and `typeof(start)`; matching only a
fabricated visible replacement would not establish persistence. Valid Unicode
and other columns keep ordinary string behavior. Invalid-surrogate persistence
on other database engines is explicitly unsupported, with no PostgreSQL claim.

Malformed installed permissions are read through actual server verification,
including mixed arrays, strings, empty requests and truthy invalid action types.
The pinned Source treats an installed string as `String.includes`; this is an
existing Source policy, only reachable here through trusted installed rows, not
a public permission over-posting capability. Wrong-owner controls preserve the
public creation/update guards. Missing owners reject only after admitted usage,
as actual Source middleware consumes quota before resolving the principal.

The same installed-permission owner also protects the exact `safeJSONParse`
date revival policy. Valid four-digit UTC ISO strings become Date objects before
authorization, so they cannot match requested strings; successful unfiltered
verification serializes them with actual Date normalization. Calendar overflow,
24:00, fractional truncation, year zero and the expanded year after 9999 are
distinct parser boundaries. Invalid month and nonzero 24:00 fractions remain
ordinary strings and retain their authorization behavior. Keys of application
objects and the original SQL permissions text remain literal. This extends the
existing owner rather than adding another parser test or a production seam.

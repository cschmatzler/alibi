# Collection callback scheduling (#332)

The uncoordinated public-list diagnostic has an observable runtime boundary:
Source awaits resolved promises and Native awaits Rust futures whose callbacks
explicitly yield to Tokio. Source's `transformSingleOutput`, `transformOutput`,
row mapper and `Promise.all` each propagate rejection through promise reactions.
Rust's nested futures propagate a ready error in the same poll. These runtimes
do not promise the same ordering of unrelated callback continuations against
aggregate rejection or the completed endpoint hook.

The installed Source factory is independently executable with:

```sh
bun tests/compat/reference-server/check-output-scheduling.mjs
```

The actual factory receives physical rows from a minimal adapter. The callbacks
record their own starts and finishes; expected receipts are not generated by the
adapter. With three fields awaiting `Promise.resolve()`, the normal row finishes
before rejection is observed. With eight equally ready fields, rejection is
observed before all normal fields finish. With a genuinely held hidden-field
promise, even the three-field normal row remains unfinished at rejection.
Releasing the held promise proves every launched normal/slow callback finishes.
The script asserts these boundaries, rather than a fixed microtask prefix.

The original fast public-list case remains available as an explicit diagnostic:
run the normal differential compatibility runner with
`BETTER_AUTH_LIST_SCHEDULING_DIAGNOSTIC=1` and filter
`diagnoses uncoordinated callback scheduler ordering`. Its full comparator
remains unchanged and reports the difference; this case is not claimed as parity
or counted as passing validation. `/tmp/issue332-fast-baseline.log` reproduces
it on main after #328: Native observes completed `/list-sessions` before the
normal omitted-field callback while Source observes that callback first. The
original discovery is `/tmp/issue328-fast-row-scheduling.log`.

The primary public SDK list table now also establishes causal order. Its normal
current session's real omitted output callback releases the rejecting sibling's
promise/Notify. Another sibling awaits a separate promise/Notify, released by
an operator only after the client received HTTP500 and inspected persisted state.
Both implementations therefore compare every actual callback, the completed
hook, error transport, and delayed callback's captured `/list-sessions` context.
All users, accounts, verifications and sessions remain unchanged; original
physical user/token authority, expiry exclusion, foreign ownership and ordered
successful collection assertions remain. The existing independent 200ms/400ms
rejection case and successful list case are retained, as is #223's replacement
continuation owner.

This is an investigation boundary, not a runtime lifecycle repair. Native's
owned collection worker already preserves launched siblings after aggregate
rejection. No production scheduler delay, yield count, comparer normalization,
callback removal, or wait for unrelated pending rows is introduced. Consumers
requiring causal order between independent asynchronous callbacks must express
that dependency in their callbacks.

Test authoring gate: the causal table protects callback dependency and owned
post-rejection continuation at the public SDK/HTTP/storage boundary. Cancellation
or prematurely discarding the worker would omit the released sibling's receipts;
propagating rejection before the ready barrier would place completed before its
callback. Earlier time-based siblings did not establish either causal dependency.
The Source characterization establishes the separate installed dependency
scheduling boundary. Neither requires a production seam. The intentionally
failing fast diagnostic records the pre-change observation without weakening it.

Final focused proof on #328's main: 24 differential SDK scenarios / 624
assertions, including unchanged list cases and replacement continuation, pass.
The causal Source-self scenario passes 56 assertions through repeated reset.
All three installed-factory characterizations, 13 native session-management
tests, strict standalone fixture Clippy, client TypeScript, changed Rust
formatting and diff checks pass. The final opt-in fast diagnostic deliberately
fails 48 assertions' full comparison at normal omitted/completed ordering
(`/tmp/issue332-fast-diagnostic-final.log`); it is separate from that passing
focused proof. Full-workspace and coverage gates were not run for this issue.
Physical account bytes, including independently salted password hashes, are
asserted unchanged against each runtime's own initial snapshot; the existing
cross-runtime public/session observations and full raw traces are preserved.

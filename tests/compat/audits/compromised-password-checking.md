# Compromised-password checking (issue #135)

Reference is the actual installed Better Auth 1.7.6 `plugins/haveibeenpwned/index.mjs` and its published declaration, plus the endpoint hashing owners. The plugin is an initialization wrapper around `context.password.hash`, not a request middleware. It preserves the original hash/verify configuration and invokes the check only when a real password hash operation reaches an included logical endpoint path. Its default exact paths are /sign-up/email, /change-password, /reset-password, /email-otp/reset-password, /phone-number/reset-password, /admin/create-user and /admin/set-user-password. An explicitly empty paths array checks none; wildcard text has no wildcard meaning. Only enabled=false bypasses the wrapper. An empty custom compromised message falls back to the published default.

`isPasswordCompromised` computes SHA-1 of the original UTF-8 password, uppercases its hexadecimal output, sends only the first five characters to the fixed range API, and compares the remaining 35 characters locally. This occurs before the original scrypt hasher's NFKC normalization. The HTTP request has Add-Padding=true and User-Agent=BetterAuth Password Checker. The first case-insensitive matching suffix line owns the result, including a zero count before a later duplicate positive count. Matching counts must be canonical decimal strings representing nonnegative JavaScript safe integers. Leading zeros, signs, whitespace, fractions, exponent text, nonfinite values and unsafe integers reject; unrelated malformed lines do not. CRLF and LF separators are accepted, but a lone final CR remains part of its count. HTTP provider errors become 500 with the actual status; other fetch/parsing errors become the generic published retry message. A positive count becomes coded400 PASSWORD_COMPROMISED with the configured/default message.

The wrapper obtains the actual current endpoint context after the enabled guard. A valid context with no path bypasses checking; a completely absent context throws. The default list excludes the trusted server-only setPassword endpoint, but an explicitly configured /set-password path includes it. No public set-password HTTP route will be added. Password verification does not invoke this hash wrapper. Configured sign-in paths can nevertheless reach it during genuine missing-user/missing-credential timing hashes; returning valid credentials do not introduce an invented check.

Ordering is owned by each actual hash call. Signup hashes before user validation/database creation hooks, including enumeration-safe duplicate signup's real timing hash. Core password reset consumes its real reset proof before hashing; email OTP and phone reset consume their real OTP before hashing. Rejection therefore burns those proofs while preserving credentials, sessions and reset callbacks. Admin creation admits and creates the user before hashing, so an authorized compromised-password failure can leave that Source user without a credential account. The audit will retain that full resulting state rather than asserting an invented rollback. Admin password setting validates authority/bounds before hashing and writes credentials afterward. Hash rejection precedes successful-reset callbacks and optional session revocation.

Implementation and proof are pending. Native will use an idiomatic initialized hash decoration with logical endpoint context separate from an optional physical request, preserving the merged #183 identity policy ordering. Controlled fixtures will use the genuine published Source plugin/helper, a bounded actual local HTTP range service, independent SHA-1 expectations and genuine password hashes, complete transport and physical state, and owned foreign-row isolation. A missing route, compiler error or wrong-origin failure will not count as pre-fix evidence. No Source runtime, comparator, allowance or coverage suppression will be changed.

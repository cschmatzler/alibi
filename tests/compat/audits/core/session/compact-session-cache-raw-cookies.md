# Compact cache raw-cookie evidence

This supplements the authenticated compact-cache comparison contract. The optional `rawCookies` observation retains every actual session-data Set-Cookie header, including tombstones, in delivery order. Authentication still requires the complete original compact token, canonical decoded envelope, original HMAC and full public-decoder result; the raw headers cannot introduce an entropy exception for an unauthenticated value.

The comparator parses each header with ToughCookie, preserves its full attributes and extensions, checks canonical URI bytes and base/chunk names, verifies the pinned 4050-byte partition and exact token reassembly, and compares header order, attributes and tombstones. Optional-field presence must agree. This first profile family uses the default HTTP cookie name and attributes; custom cookie prefixes/security attributes and broader public-helper malformed-chunk parsing remain separate coverage boundaries.

The primary harness uses two actual Better Auth 1.7.6 applications and its published cookie decoder. The default 32-character ID generator and an application UUID36 generator produce different final chunk lengths while preserving the same cache behavior. This corrects a newly introduced derived-length assertion: exact final lengths depend on legitimate ID entropy. Every raw header and authenticated claim remains observable. Removal, addition, reordering, truncation, noncanonical indices, missing HttpOnly, changed Path/extensions and altered tombstones fail the comparator. The source writer is `cookies/session-store.mjs` (`MAX_COOKIE_SIZE = 4050`, chunk capacity calculated with `.99`).

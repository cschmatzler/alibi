# Stateful compact session-cookie cache

This is the first implemented cookie-cache family for pinned Better Auth 1.7.6. It supplements the source-only investigation in `session-cookie-cache.md`; that earlier audit describes the native implementation before this change. It does not establish parity for the other cache strategies or every plugin guard.

## Implemented contract

Enabled compact caching now emits authenticated session-data cookies from the genuine issued user/session pair and reads them before the database on the explicitly migrated ordinary guards: get-session, organization extension handlers and organization list, account list/unlink, and anonymous session resolution. The physical public native `require_session` API remains authoritative. Cached data is represented by `AuthenticatedUser::Cached(UserView)` rather than a fabricated database model; all other ordinary guards remain a separate migration boundary. Sensitive anonymous deletion continues to read physical state.

The compact codec ports the source original-JSON HMAC, complete envelope, safeJSONParse date revival, required payload fields, signed session-token binding, outer and embedded session expiry, version validation and storage fallback. A cache containing another owner's token cannot grant authority even with a valid cache signature. Storage revocation intentionally does not invalidate an unexpired stateful cache on these ordinary guards; an explicit cache bypass observes actual revocation. No cached model is re-created or looked up merely to satisfy a callback.

`CookieCacheConfig.max_age` now uses raw numeric seconds, replacing the previously advertised but inactive Duration property. Callers using `Duration::seconds(n)` must supply `n as f64`. Zero and NaN use the source 300-second default, fractional values retain their millisecond expiry and floor the Max-Age header, and negative values omit Max-Age while retaining their signed past expiry. Negative infinity emits a signed null expiry which the public reader rejects. Positive infinity and cookie ages beyond the serializer maximum fail actual emission. Browser preference comes only from the validated endpoint option or signed dontRemember cookie and uses 60 seconds with browser-session cookie attributes.

Version policies are immutable literal strings or application-owned async callbacks. `CacheVersionSource::Created` retains the actual typed application models alongside canonical output views; its downcast accessors expose genuine originals. `Stored` receives the source findSession filtered projection and has no original-model accessors. `Cached` receives authenticated filtered views only. This distinction is necessary: the source creation callback observes hidden physical fields, while stored renewal and cache reads do not. Request-local preference and queued-cookie state are reset at public dispatch.

Cache issuance is awaited before the original completed-session snapshot is published. Real ordinary callback failures skip after hooks and return empty500 without final cookies; explicit application API errors retain source queued token/preference headers but no completed snapshot. Email signup transaction rollback still removes the new user/session. Anonymous after hooks retain the source old-session read order without inventing a successful issuance snapshot. Cache headers enter the response before plugin after hooks so a later two-factor scrub can remove them. No new generic error mapping or storage transaction was introduced.

The source session-store writer uses 4050-byte headers, `.99` partition capacity, canonical chunk indices and at most 100 chunks. Every actual raw cookie header is retained through the authenticated evidence atom, including ordered tombstones and complete attributes. Independent reassembly and header validation protect truncation and mutation. The published cookie helper uses a different permissive parseInt chunk reader than the HTTP canonical reader; malformed helper chunks remain an explicit integration boundary.

The existing private encrypted-account-cookie lifetime pipeline mechanically consumes the same raw numeric seconds. It retains source falsy defaults, finite fractional/negative expiry and actual cookie serialization; nonfinite JWT expiry rejects rather than saturating. The source-only account lifetime probe records +Infinity callback failure with user/account retained and no session. This pipeline adaptation does not claim a complete account-cookie TTL differential family.

## Remaining boundaries

Enabled JWT and JWE cache strategies fail closed with a typed configuration error; disabled unused strategies remain accepted. Stateless refresh/cache-only session mode, secret rotation, cache-refresh configuration, external managed JWKS and the remaining ordinary plugin guards are unimplemented or unproved here. Native two-factor scrub/verification and signed-email original snapshot/cache-version projection require their own combined runtime owners despite source probes. This slice uses the default cookie naming/security attributes; custom prefixes/attributes, large-cookie overflow, public malformed-chunk parser equivalence and encrypted account TTL combinations need additional owners.

The reader ports the pinned four-digit ISO-Z date revival used by these producers. Expanded-year dates, engine-specific legacy dates, malformed UTF8/BOM, JavaScript prototype/undefined/user-ID coercion and arbitrary application user additional-field projection are wider compatibility boundaries. Typed original application-session downcasts are proven; no arbitrary SQL columns are inferred as public fields. Backend secondary-storage-only sessions and custom session/account schema behavior outside the stated real SQLite model remain separate. HTTP disconnect/task continuation and global trusted server dispatch are not established by these cache controls.

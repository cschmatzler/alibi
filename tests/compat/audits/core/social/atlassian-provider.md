# Atlassian provider contract (issue #140)

The independent authority is the actual published Better Auth 1.7.6 `@better-auth/core/dist/social-providers/atlassian.mjs`, its declared profile/options, `oauth2/create-authorization-url.mjs`, token helpers, and `better-auth/dist/oauth2/account-key.mjs`. The official-client primary owner is `tests/core/social/atlassian.test.ts`. Source invokes the unchanged published factory. Only its fixed token (`auth.atlassian.com/oauth/token`) and user-info (`api.atlassian.com/me`) HTTP destinations redirect to deterministic local HTTP. Controls supply endpoint responses, never fabricated admission, callback receipts, or rows. Native invokes the new public options/factory and real SeaORM SQL. The existing social-provider state observer retains every user/account/session column and foreign principals.

Authoring gate: the table owners protect the missing provider's fixed audience, default/configured scope order and PKCE; independent raw-subject/profile mapping; actual code/token/userinfo exchange; callback state replay; signup and verified-email policy; actual owned refresh rotation and logout. Credible regressions include omitting the audience, falling back to an email-derived name, replacing a raw account key with a mapper ID, replaying an issued state, or rotating another owner's credentials. Existing generic/configured-verifier and other-family tests do not execute the Atlassian factory or profile shape. Each behavior has one official SDK/HTTP/SQL owner, rather than duplicate helper tests. The trusted custom user-info endpoint is an application transport interface like the existing GitHub endpoints; it does not bypass mapping or admission.

## Factory and supported policy

`OAuthProvider::atlassian` / `atlassian_with_options(AtlassianOptions)` uses fixed authorization/token/user-info endpoints, ordered `read:jira-user offline_access`, configured then requested scopes (including duplicates), S256 PKCE, required client ID/secret, response type `code`, fixed `audience=api.atlassian.com`, and configured prompt. `disable_default_scope`, an application authorization endpoint, and `redirect_uri` are supported. The shared authorization policy now retains the configured callback at both authorization and token exchange. Request login hints and configured `responseMode` are ignored by this published factory. Token endpoint authentication is form `client_secret_post`. There is no provider default expiry: absent/zero `expires_in` persists null; a finite fractional expiry retains millisecond precision. No configured issuer or discovery endpoint exists in the pinned options.

Raw `account_id` establishes the independent stable account subject, even after profile mapping. Finite numeric account IDs use JavaScript number-string formatting. Missing/null/empty subjects reject without SQL writes. The actual Source workflow persists missing/null/empty or numeric-zero names as `""`, finite nonzero numeric names as strings, and missing/null pictures as null. Numeric pictures `7` and `0` persist as strings `"7"` and `"0"`. Email absence/null/empty rejects before creating users. Numeric email is outside the declared string/email shape: an exploratory actual Source probe returned `internal_server_error` with no writes; no compatibility claim is made for arbitrary objects/arrays as names, subjects, emails or images. Native's callback interface provides an idiomatic typed user and preserves the complete original profile for application mapping; the mapped ID cannot replace `account_id`. Default email verification is false. An application mapper can supply verified email/name/image, and the ordinary generic callback overrides remain configurable on the returned provider.

The provider has no built-in ID-token/JWKS/nonce/audience verifier. An untrusted ID token returns `ID_TOKEN_NOT_SUPPORTED` with no provider requests or rows; pretending to exercise issuer/signature cryptography for this factory would test an unsupported feature. Generic application verifier/user-info overrides remain available. Refresh uses the actual fixed token service and original client ID/secret; no refresh scope, prompt, audience, PKCE, or callback URL is fabricated. The published factory has no provider logout; the owner verifies normal local session revocation and absence of an outbound logout request.

## Native interface and protocol

`OAuthProvider::notion` and `notion_with_options(NotionOptions)` use `https://api.notion.com/v1/oauth/authorize`, `https://api.notion.com/v1/oauth/token`, and GET `https://api.notion.com/v1/users/me`. No default scopes exist; configured then requested scopes retain duplicates and order. Empty scopes omit the parameter. Disabling defaults makes no difference to the empty default set. A configured authorization endpoint and redirect URI are supported. Authorization requires a client ID, forwards nonempty login hints and additional parameters, and overwrites caller `owner` with `user`. No PKCE, nonce, issuer or discovery policy exists. Prompt and response mode options are not forwarded by this factory; caller additional parameters remain supported subject to the shared reserved-parameter guard.

Code exchange requires client ID and secret, uses RFC 6749 encoded Basic credentials, and omits credentials and PKCE from its form. An optional client key appears only in code exchange. Refresh uses client-secret-post; its factory constructs a fresh credential-only options object, so code-only client key and redirect overrides are absent from the refresh form. An application refresh callback remains available on the returned provider. Token redirects are refused by the shared token transport. Missing or zero expiry remains null, and fractional expiry retains milliseconds.

## Profile and persistence

GET user information sends the access-token bearer and `Notion-Version: 2022-06-28`. `bot.owner.user` is the actual profile, not the bot or workspace. Absent/null owner and HTTP failure deny admission. The mapper receives the complete original owner before raw subject validation. Account subject derives independently from owner `id`; missing/null/empty IDs deny and numeric IDs use JavaScript string formatting. A mapper ID remains public profile data and cannot replace persisted account identity.

Name uses JavaScript truthiness with an empty-string fallback, including missing/null/empty/zero. Email uses `person.email` with a null fallback; absent/null/empty email denies signup. Default verification is false. Avatar absence remains absent in account info, null remains null and empty remains empty; scalar numeric profile values retain raw account-info JSON and typed persistence. Arbitrary object/array fields and numeric email are outside the declared profile shape and are not claimed. Mapping can override name, email, image and verification. Existing account-info reads do not establish a new account subject.

The returned generic provider supports signup, verification and asynchronous user-info/refresh policies. This scoped owner covers default factory behavior, mapped profiles, explicit/implicit signup policy and the verified-email gate. Dedicated application override callback and encrypted-token permutations remain shared OAuth-owner coverage rather than a Notion-specific completeness claim. Broader full-suite and instrumented source-coverage proof remains coordinator-owned; issue #154 is not closed by this scoped PR.

# Raw organization quotas: Better Auth 1.7.6 (#218)

The published `better-auth@1.7.6` tarball is the reference. Both fixture installs were checked byte-for-byte against the archive after verifying its npm SHA-512 integrity (`sha512-WTMqOpmTTj+oBoX7zzPOzL85342Upyf+/v0IkH1kvGRA85lV4JGRFIYMIRKqvjZ6ShsuL5VX/c9C13jtoZXcKA==`). Source package files were never mutated; negative controls change the owned native implementation.

The numeric fixed/async runtime matrix was measured before choosing the native API. Native quotas and `OrganizationLimitResolver` returns now use `Option<f64>` in the existing fields. Store seat policies use the same raw type throughout transaction and adapter forwarding. No competing configuration fields, membership-policy defaults, numeric clipping, or query-value rounding are introduced.

| Policy | 0 | 1.5 | -1.5 | NaN | +Infinity | -Infinity | Unset |
| --- | --- | --- | --- | --- | --- | --- | --- |
| maximumTeams | unbounded | admits two | denies | unbounded | unbounded | denies | unbounded |
| maximumMembersPerTeam | denies new seats | admits two | denies | denies (SQLite predicate) | unbounded | denies | unbounded |
| maximumRolesPerOrganization | denies | admits two | denies | unbounded | unbounded | denies | unbounded |

“Unbounded” describes these quotas, not other admission or authorization checks. Teams use Number truthiness followed by `existingTeams.length >= maximum`. That list is read before the callback, and retains the Source adapter's configured list page. Roles use a nullish default of positive infinity and a full persisted count read after the callback. Neither organization-level quota becomes an atomic capacity reservation.

Members use Source's database seat predicate `memberCount < maximumMembersPerTeam`, after upward synchronization of a stale low counter. Existing membership wins before reservation, making retries idempotent even at capacity. Both native adapters bind the actual raw `f64` to SQL rather than approximating this predicate in Rust; SQLite binding of NaN produces NULL and denies a seat. High durable counters remain high. The transaction/row-lock implementation retains the preexisting seat boundary; no stronger organization-capacity atomicity is claimed. Cross-driver nonfinite behavior remains #192.

## Public migration

Integer configurations change `maximum_teams: Some(3)` to `maximum_teams: Some(3.0)`; apply the same change to member and role fields. Integer resolver implementations change `AuthResult<Option<usize>>` to `AuthResult<Option<f64>>` and return `Some(3.0)`. Existing asynchronous contexts, error propagation, resolver precedence, and ordinary integer admission behavior remain intact; the team read snapshot and HTTP timestamp are now chosen in the Source order. Integer application policies may explicitly convert their integer to `f64` at the policy boundary; this adopts JavaScript Number precision, including beyond 2^53. Custom `TeamStore`/transaction implementations and callers likewise migrate their quota argument and invitation team-policy tuples to `Option<f64>`. `None` means an unset native policy and maps to the corresponding unlimited numeric path; it never borrows the organization-membership limit's default.

Rust callbacks can capture application stores and configuration, return raw numeric values, and observe the existing user/session/request context. They do not execute arbitrary JavaScript, expose the entire JavaScript endpoint-context object, or model dynamically invalid callback returns such as strings, objects, null or undefined. In particular a JavaScript role callback returning null compares as zero, and an undefined member callback may reach adapter-specific invalid binding; neither is represented by Rust `None`. These are explicitly outside the typed Number callback contract. No production test-only scheduling or callback injection seams were added.

## Evidence and authoring gate

`client-tests/tests/plugins/organization/raw-limits.test.ts` is the primary numeric public-contract owner. Its table exercises fixed and asynchronous zero, fractional, negative and nonfinite policies plus an unset fixed policy through the official SDK. It retains the complete responses and traces, callbacks and hook order, raw stored teams/members/roles/invitations, unchanged foreign organization state, precise public denials, and real session state. The shared comparator is unchanged: every field and relationship is still compared.

Callback receipts prove the actual owner and session user IDs, explicit organization versus the different active organization, HTTP request method/header, actual organization lookup, target user, and team ID. Wrong-owner and wrong-team requests cannot invoke the policies. A callback writes two teams before returning 1.5: the endpoint still admits using its earlier list snapshot. A role callback writes two roles before returning 1.5: the endpoint denies using the later full count. Controlled server-only team creation records absent user/session/request context. These are ordinary configured application callbacks over real stores, not a fixture simulating admission.

Concurrency evidence includes simultaneous retries of the same user at a fractional capacity, denial of a third user, removal/replacement and complete stored counter/identity checks. The existing independent-store regression now uses 1.5: eight separate connections competing for seats admit exactly two distinct users, preserve retries and release seats. A Source/native hook sets a high legacy counter before admission; two attempts deny and preserve that physical counter with no inserted membership, retaining the complete deliberately inconsistent state instead of normalizing it.

These cases protect independent public numeric, callback, SQL-binding, persistence and concurrency contracts. Credible regressions include integer truncation, treating NaN as a Rust `>=` comparison, truthiness reuse for seats/roles, omitting real principals, moving team reads after policy evaluation, counting roles before it, resetting high counters, and consuming a second seat on retry. Existing integer coverage could not represent the raw policies; existing concurrency coverage did not exercise fractional capacities. No new production seam is needed.

The integer-only baseline with the closest representable fractional quota (1) rejects the second team against the raw Source 1.5 expectation on both SQLx and SeaORM. This establishes the public representation gap; it does not claim the old API accepted a fractional argument. The callback-write regression also failed on both repaired numeric adapters before the timestamp-order correction: stored readback placed the endpoint team ahead of the callback-created teams. Choosing the HTTP timestamp after policy evaluation repairs this without array normalization or changing explicitly supplied trusted-native timestamps. Additional owned native mutation controls and final focused validation are recorded in the PR and the worker's preserved evidence logs. Targeted API/storage tests, SDK scenarios on both actual backends, Clippy, TypeScript, formatting and self-review are run without invoking the full compatibility gate.

Final owned validation: 16 SDK scenarios / 1,060 assertions on each actual SQLx and SeaORM SQLite fixture; seven existing targeted storage contracts on each adapter; 28 native organization API tests; strict Clippy for changed crates/all targets and the fixture on both features; TypeScript, focused oxlint/oxfmt, Rust formatting and diff checks. The seven native mutation cases all fail for their intended public reasons on each adapter: seat `<=` (two zero cases), omitted callback user, reading teams after the callback, bypassing the NaN SQL predicate (fixed/async), and lowering a high durable counter. Original files were restored before the final rebase and affected dual-store rerun.
